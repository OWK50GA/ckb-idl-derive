# schnorr-pubkey-recovery

> ⚠️ **Hand-written example. This IDL was not generated by `ckb-idl-derive`.** It is a reference illustration of what the macro output would look like for this lock script pattern.

**Lock type:** Schnorr signature with optional inline public key  
**Source:** —  
**Status:** Hand-written example

## Witness layout

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `signature` | `schnorr_sig` | yes | 64-byte Schnorr signature (R \|\| s) |
| `pubkey` | `secp256k1_pubkey` | no | 33-byte compressed public key; omit if stored in args |

## Notes

- Relevant for RGB++ lock scripts and Bitcoin-compatible CKB lock designs.
- The `required = false` on `pubkey` demonstrates the IDL's ability to express conditional fields.
- A PSCT coordinator using this IDL knows it can finalise the transaction without `pubkey` if the script's args already contain the key.
- This is the first IDL in this collection that uses `schnorr_sig` — a good test of the `[u8; 64]` registry mapping.
